# Ошибка Permission Denied в Claude Code

**Проблема**: Claude Code возвращает ошибку «Permission denied» при попытке выполнить bash-команды, установить пакеты, отредактировать файлы или получить доступ к директории `~/.claude/`.

Это одна из самых распространённых проблем у новых пользователей Claude Code. Ошибка обычно указывает на одну из трёх основных причин — и каждая из них имеет чёткое решение.

---

## Причина 1: Глобальные права npm

Самый частый источник проблемы. Когда Claude Code пытается установить или запустить npm-пакет глобально, а системная директория npm принадлежит root, вы видите:

```
Error: EACCES: permission denied, mkdir '/usr/local/lib/node_modules/...'
```

или в выводе Claude Code:

```
Bash tool error: permission denied running npm install -g ...
```

### Решение

Правильный подход — перенастроить npm на использование директории, доступной для записи пользователем, а не `sudo npm`. Использование sudo с npm нарушает безопасность пакетов и создаёт ещё больше проблем с правами доступа.

**Шаг 1**: Создайте директорию для глобальных npm-пакетов:
```bash
mkdir -p ~/.npm-global
```

**Шаг 2**: Настройте npm на её использование:
```bash
npm config set prefix '~/.npm-global'
```

**Шаг 3**: Добавьте в PATH. В `~/.bashrc` или `~/.zshrc`:
```bash
export PATH="$HOME/.npm-global/bin:$PATH"
```

**Шаг 4**: Перезагрузите shell:
```bash
source ~/.bashrc   # или ~/.zshrc
```

После этого глобальные установки npm выполняются без root и без sudo. Claude Code может свободно их запускать.

**Проверка**: Запустите `npm install -g cowsay && cowsay "работает"` без sudo. Если всё прошло успешно — исправление применено.

---

## Причина 2: Права доступа к директории `~/.claude/`

Если ваша директория `~/.claude/` или её содержимое были созданы другим пользователем (это может случиться после запуска Claude Code с sudo или после восстановления системы), Claude Code не может читать или записывать свои настройки.

Симптом: Claude Code запускается, но сразу не может прочитать настройки, или изменения настроек не сохраняются.

```bash
ls -la ~/.claude/
```

Ищите файлы, принадлежащие `root` или другому пользователю, а не вашему имени.

### Решение

**Вариант A**: Если директория принадлежит root:
```bash
sudo chown -R $(whoami):$(whoami) ~/.claude/
```

**Вариант B**: Если отдельные файлы имеют неверные права:
```bash
chmod -R u+rw ~/.claude/
```

**Вариант C** (радикальный, только если ничего не помогает): Сначала сделайте резервную копию настроек, затем удалите директорию и дайте Claude Code пересоздать её:
```bash
cp -r ~/.claude/ ~/claude-backup/
rm -rf ~/.claude/
# Перезапустите Claude Code — он пересоздаст директорию с правильными правами
```

После исправления владельца перезапустите Claude Code и убедитесь, что он читает ваши настройки — проверьте, появляются ли настроенные инструменты в новой сессии.

## Причина 3: Bash-инструмент заблокирован в настройках

Bash-инструмент Claude Code может быть явно заблокирован в вашем `~/.claude/settings.json` или в `.claude/settings.json` на уровне проекта. Это намеренное поведение при соответствующей настройке, но часто происходит случайно.

Симптомы:
- Claude Code говорит, что выполняет команду, но ничего не происходит
- Вы видите сообщение вроде «Bash tool is not allowed for this session»
- Команды работают в одном проекте, но не в другом

### Решение

**Шаг 1**: Проверьте глобальные настройки:
```bash
cat ~/.claude/settings.json
```

Найдите массив `blockedTools` или секцию `permissions.deny`, включающую `Bash`:

```json
{
  "permissions": {
    "deny": ["Bash"]
  }
}
```

**Шаг 2**: Удалите ограничение Bash. Минимальное исправление:
```json
{
  "permissions": {
    "allow": ["Bash"],
    "deny": []
  }
}
```

**Шаг 3**: Проверьте также файл настроек на уровне проекта, если он существует:
```bash
cat .claude/settings.json
```

Настройки проекта переопределяют глобальные, поэтому блокировка на уровне проекта запретит bash, даже если глобальная настройка его разрешает.

**Шаг 4**: Перезапустите Claude Code и протестируйте простой командой:
> «Выполни `echo hello` в bash»

Если проблема была в Bash-инструменте — теперь это заработает.

## Советы по предотвращению

**Никогда не запускайте `claude` через `sudo`**: Это создаёт файлы в `~/.claude/`, принадлежащие root, что ломает последующие запуски от имени обычного пользователя. Если вы случайно запустили с sudo — см. Причину 2 выше.

**Используйте настройки на уровне проекта для ограничений**: Если вы хотите ограничить доступ к bash в конкретном репозитории (например, работа рядом с продакшеном), поместите ограничение в `.claude/settings.json` внутри этого репозитория — не в глобальные настройки.

**Проверяйте права после восстановления системы**: Если вы восстановили домашнюю директорию из резервной копии, проверьте владельца `~/.claude/` перед запуском Claude Code.

**Используйте список `allowedTools` для разрешений, а не блокировок**: Вместо того чтобы блокировать всё и разрешать конкретные инструменты, чище определить, какие bash-команды разрешены, используя шаблон `permissions.allow` с явными паттернами команд.
