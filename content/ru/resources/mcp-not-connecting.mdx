# MCP в Claude Code не Подключается

**Проблема**: MCP-сервер, настроенный в Claude Code, недоступен в сессиях — инструменты не появляются, или при попытке Claude вызвать MCP-инструмент возникает ошибка подключения.

Сбои подключения MCP имеют небольшой набор хорошо известных причин. Пройдите по этому руководству по диагностике по порядку — и вы найдёте проблему.

---

## Симптомы

- Claude Code запускается, но ожидаемые MCP-инструменты не отображаются при вопросе «какие инструменты у вас есть?»
- Claude пытается вызвать MCP-инструмент и возвращает: `MCP server connection failed` или `Tool unavailable`
- MCP-сервер отображается в настройках, но Claude говорит, что не может его достичь
- MCP работал раньше и перестал после перезапуска системы или изменения настроек

---

## Причина 1: Неверный JSON в настройках

Это самая частая причина. Одна синтаксическая ошибка в `~/.claude/settings.json` или в `.claude/settings.json` на уровне проекта тихо помешает загрузке MCP-серверов.

### Диагностика

Проверьте файл настроек:
```bash
cat ~/.claude/settings.json | python3 -m json.tool
```

Если это выводит ошибку разбора JSON — проблема найдена. Распространённые ошибки:

- Запятая в конце после последнего элемента объекта или массива: `"key": "value",}` — запятая перед `}` — неверный JSON
- Одинарные кавычки вместо двойных: `'key': 'value'` — JSON требует двойные кавычки
- Отсутствующая запятая между элементами
- Переносы строк в стиле Windows, создающие невидимые символы

### Решение

Откройте файл настроек в редакторе с поддержкой JSON (VS Code подсветит ошибку). Исправьте синтаксическую ошибку и повторно запустите валидатор. Когда валидатор выводит корректно отформатированный JSON без ошибок — перезапустите Claude Code.

---

## Причина 2: Процесс MCP-сервера не запущен

Для MCP-серверов с транспортом HTTP/SSE (с URL в конфигурации вместо команды) серверный процесс должен быть запущен до подключения Claude Code. Если сервер остановился (сбой, перезапуск системы, Docker-контейнер остановлен), Claude Code не к чему подключаться.

### Диагностика

Проверьте, запущен ли процесс:
```bash
# Для локального процесса на порту 3000:
lsof -i :3000
# Или:
curl http://localhost:3000/health
```

Если на ожидаемом порту ничего не слушает — сервер не работает.

### Решение

Перезапустите процесс MCP-сервера. Точная команда зависит от способа установки:

```bash
# Пример: MCP-сервер на npm
node /path/to/mcp-server/index.js &

# Пример: MCP-сервер на Docker
docker start my-mcp-server

# Пример: сервис под управлением systemd
systemctl start my-mcp-server
```

Чтобы предотвратить повторение, настройте MCP-сервер как системный сервис (systemd на Linux, launchd на macOS) для автоматического запуска при загрузке.

---

## Причина 3: Конфликт порта

Другой процесс использует порт, на котором настроен ваш MCP-сервер. MCP-сервер не запускается или запускается на другом порту.

### Диагностика

```bash
# Проверьте, что занимает ожидаемый порт:
lsof -i :PORT_NUMBER
# или:
ss -tlnp | grep PORT_NUMBER
```

### Решение

Вариант A: Остановите конфликтующий процесс, если это безопасно.

Вариант B: Перенастройте MCP-сервер на другой порт, затем обновите порт в `~/.claude/settings.json`.

После смены порта снова проверьте JSON настроек и перезапустите Claude Code.

---

## Причина 4: Несоответствие транспорта

MCP-серверы поддерживают два механизма транспорта: **stdio** (запускается как дочерний процесс) и **HTTP/SSE** (работает как сетевой сервис). Если файл настроек указывает неверный транспорт для того, как сервер реально запускается, подключение тихо завершится ошибкой.

### Диагностика

Проверьте запись настроек для MCP-сервера:
```json
{
  "mcpServers": {
    "my-server": {
      "command": "node",
      "args": ["/path/to/server.js"]
    }
  }
}
```

Формат `command` / `args` = транспорт stdio (Claude запускает процесс).

```json
{
  "mcpServers": {
    "my-server": {
      "url": "http://localhost:3000/sse"
    }
  }
}
```

Формат `url` = транспорт HTTP/SSE (сервер уже должен быть запущен).

Если вы используете `url`, но сервер ожидает запуска, или используете `command`, но сервер уже работает как сервис — подключение завершится ошибкой.

### Решение

Приведите формат настроек в соответствие с тем, как спроектирован ваш MCP-сервер. Проверьте README сервера — там будет указано, использует ли он транспорт stdio или HTTP. Обновите настройки для использования правильного формата.

---

## Пошаговый чеклист диагностики

Выполните по порядку:

1. `cat ~/.claude/settings.json | python3 -m json.tool` — проверьте синтаксис JSON
2. Проверьте настройки на уровне проекта: `cat .claude/settings.json | python3 -m json.tool`
3. Убедитесь, что процесс MCP-сервера запущен (для HTTP-транспорта)
4. Проверьте конфликты портов на ожидаемом порту
5. Убедитесь, что тип транспорта соответствует дизайну сервера
6. Проверьте логи сервера на ошибки запуска (обычно в `~/.mcp-server-name.log` или терминале, где вы его запустили)
7. Протестируйте сервер отдельно: для HTTP-серверов `curl http://localhost:PORT/health` должен вернуть 200

## Советы по предотвращению

**Используйте транспорт stdio для локальных одиночных установок**: MCP-серверы stdio запускаются по требованию Claude Code — нет отдельного процесса для управления, нет порта для настройки. HTTP/SSE предназначен для общих командных серверов или серверов, которым нужно сохранять состояние.

**Валидируйте JSON после каждого редактирования**: Возьмите за привычку запускать `python3 -m json.tool` перед перезапуском Claude Code после редактирования настроек.

**Логируйте запуск MCP-сервера**: Для HTTP-серверов всегда перенаправляйте вывод запуска в лог-файл для диагностики сбоев: `node server.js >> ~/.mcp-server.log 2>&1`.
