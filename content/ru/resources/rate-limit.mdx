# Лимит Запросов Claude Code

**Проблема**: Claude Code возвращает ошибку лимита запросов посреди сессии. Работа останавливается, контекст прерывается, и вам приходится ждать перед продолжением.

Лимиты запросов — это ограничение API на количество токенов, которые вы можете отправлять или получать в заданном временном окне. Вот что их вызывает, как понять, где вы находитесь, и как работать в этих рамках.

---

## Что Вызывает Лимиты Запросов

Лимиты запросов Claude Code работают по двум осям: **запросы в минуту** (RPM) и **токены в минуту** (TPM). Интенсивные сессии гораздо чаще достигают лимитов TPM, чем RPM.

**Операции с высоким потреблением токенов, быстро исчерпывающие лимиты**:

- Чтение больших файлов в контекст — файл в 3000 строк, переданный модели, это 3000+ токенов входных данных
- Длинные диалоговые сессии, где контекст растёт с каждым сообщением
- Одновременный запуск нескольких параллельных субагентов (каждый потребляет токены независимо)
- Генерация длинных ответов: полные тест-сьюты, крупные рефакторинги, полные переписывания компонентов
- Повторные попытки после сбоя вызова инструмента (каждая повторная попытка повторно отправляет контекст)

**Признаки приближения к лимиту запросов** (до достижения жёсткой ошибки):
- Ответы становятся заметно медленнее
- Вызовы инструментов занимают больше времени
- Вы видите неполные ответы до того, как API обрывает их

## Как Проверить Текущие Лимиты

Лимиты запросов зависят от вашего тарифного уровня Anthropic. Чтобы узнать, где вы находитесь:

**Через консоль Anthropic**:
1. Перейдите на [console.anthropic.com](https://console.anthropic.com)
2. Перейдите в **Настройки → Лимиты**
3. Ваши текущие лимиты RPM и TPM перечислены по уровням модели

**В сессии**: Claude Code не отображает счётчик токенов в реальном времени, но вы можете спросить Claude посреди сессии: «Сколько контекста у нас осталось?» — он даст приблизительную оценку.

**Из сообщения об ошибке**: При достижении лимита ответ об ошибке содержит заголовок `retry-after`, указывающий, сколько секунд ждать.

## Стратегии для Предотвращения Лимитов Запросов

### Регулярно Используйте `/compact`

Самый эффективный инструмент. Запуск `/compact` в Claude Code суммирует разговор и заменяет полную историю сообщений сжатой версией. Это резко сокращает количество токенов в контексте, который Claude несёт дальше.

Запускайте `/compact` после завершения крупной подзадачи — после завершения рефакторинга, после разрешения отладочной сессии, перед началом новой функции. Думайте об этом как о расчистке рабочего стола.

### Сократите Количество Параллельных Агентов

Если вы запускаете мультиагентные рабочие процессы, где несколько субагентов выполняются одновременно, каждый из них сжигает токены параллельно. Достичь лимита посреди работы агента хуже, чем медленная сессия, потому что это прерывает незавершённую работу.

Для тяжёлых параллельных нагрузок: чередуйте выполнение агентов (запускайте 2 за раз вместо 5) или используйте модель нижнего уровня для простых субагентов, оставляя полную модель для оркестратора.

### Ограничивайте Чтение Файлов

Избегайте вставки или чтения целых больших файлов, когда вам нужна только часть. Вместо «прочитай всю кодовую базу» запрашивайте конкретные функции или файлы. Инструменты файловой системы Claude Code могут читать конкретные диапазоны строк — используйте их.

```
Прочитай строки 120–180 из src/auth/middleware.ts
```

вместо чтения всего файла.

### Группируйте Запросы Там, Где Возможно

Если вы просите Claude сделать 10 похожих вещей (переименовать 10 переменных, сгенерировать 10 тест-кейсов), объедините их в один запрос, а не 10 последовательных. Один большой запрос использует меньше токенов, чем 10 итераций с повторяющимся контекстом.

### Перейдите на Более Высокий Тариф

Если вы постоянно достигаете лимитов при обычной работе, ваше использование переросло текущий тарифный уровень. Более высокие уровни Anthropic предлагают значительно более высокие лимиты TPM. Проверьте [страницу тарифов Anthropic](https://anthropic.com/pricing) для актуальных лимитов.

Для команд, где несколько разработчиков одновременно ведут интенсивные сессии, потребление токенов на разработчика суммируется — командные аккаунты на более высоких уровнях являются правильным решением.

## Профессиональные Советы

**Начинайте новые сессии для новых задач**: Свежая сессия начинается с нулевым контекстом. Если вы работали в длинной сессии и приближаетесь к лимитам, завершить её и начать заново для следующей задачи — часто самое чистое решение.

**Используйте `CLAUDE.md` вместо повторных объяснений контекста**: Если вы обнаруживаете, что вводите одну и ту же фоновую информацию каждую сессию — это зря потраченные токены. Поместите её в файл `CLAUDE.md` — Claude читает его автоматически, и вам не нужно платить за повторные объяснения каждый раз.

**Следите за длиной сессии на больших задачах**: Для задач, которые будут выполняться часами (крупные миграции, полные рефакторинги кодовой базы), планируйте контрольные точки `/compact` заранее. Не ждите, пока достигнете лимита посреди задачи.
