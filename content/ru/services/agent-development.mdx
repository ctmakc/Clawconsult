# Разработка Пользовательских ИИ-агентов

Одна сессия Claude Code может многое. Хорошо спроектированная мультиагентная система может выполнять работу, которая заняла бы у вашей команды дни — автоматически, параллельно, с журналами аудита.

Мы строим **пользовательские агенты Claude Code и мультиагентные рабочие процессы**, автоматизирующие сложные инженерные задачи: координированная генерация кода, автоматизированные пайплайны ревью PR, автономное написание тестов, ассистенты миграции репозиториев и многое другое. Если вы можете описать рабочий процесс — мы можем построить агента, который его выполнит.

## Что Мы Строим

### Системы Оркестратор + Субагенты

Наиболее мощный паттерн Claude Code: **агент-оркестратор**, который разбивает высокоуровневую цель на подзадачи и распределяет **специализированных субагентов** для обработки каждой из них параллельно.

Пример: оркестратор миграции, который читает весь ваш каталог `src/`, распределяет по одному субагенту на модуль для конвертации CommonJS в ESM, собирает результаты, запускает субагент-валидатор для проверки ошибок импорта и создаёт отчёт о миграции — всё без участия человека.

Мы проектируем стратегию декомпозиции задач, протокол взаимодействия между агентами и логику агрегации результатов. Мы также строим слой безопасности: агенты, которые могут приостановиться и запросить человеческое ревью при встрече с неоднозначностью.

### Автоматизированные Агенты Ревью Кода

Агент ревью кода, запускаемый на каждый PR, который:

- Проверяет на антипаттерны безопасности (захардкоженные учётные данные, векторы SQL-инъекций, XSS-риски)
- Верифицирует покрытие тестами для изменённых файлов
- Выявляет нарушения архитектурных соглашений вашей команды
- Генерирует inline-комментарии к PR через MCP GitHub
- Публикует сводное ревью с вердиктом pass/fail

Это не lint-скрипт — это агент рассуждений, понимающий контекст. Он читает описание PR, смотрит на diff в соотношении с полным файлом и принимает взвешенные решения.

### Автономные Агенты Написания Тестов

Направьте агента на модуль с недостаточным покрытием тестами. Он читает исходник, понимает ожидаемое поведение, пишет юнит-тесты, запускает их, диагностирует сбои и итерирует до прохождения тест-сьюта. Результат: PR с новыми файлами тестов, готовый к ревью.

### Ассистенты Миграции Репозиториев

Долгосрочные агенты для многодневных задач:

- Миграции фреймворков (React class components → hooks, jQuery → vanilla JS)
- Миграции языков (Python 2 → 3, JavaScript → TypeScript)
- Обновления зависимостей с автоматическим исправлением изменений сломанного API
- Реструктуризация монорепозитория

Мы проектируем их с контрольными точками, чтобы агент мог быть приостановлен и возобновлён, и с воротами человеческого ревью после каждого значительного пакета.

### Агенты Автоматизации Пользовательских Рабочих Процессов

Любой повторяемый инженерный рабочий процесс, который сейчас требует ручных шагов и переключения контекста, является кандидатом. Типичные примеры, которые мы строили:

- **Агент реагирования на инциденты**: читает алерт PagerDuty, извлекает релевантные логи через MCP, ищет в кодовой базе связанные недавние коммиты, составляет гипотезу о первопричине и публикует в Slack
- **Агент онбординга**: по GitHub-нику нового члена команды генерирует персонализированный список для чтения из ваших файлов CLAUDE.md, последних PR и архитектурной документации
- **Агент заметок о выпуске**: читает слитые PR с последнего релиза, группирует по категориям и создаёт читабельный changelog в стиле вашей команды

## Пример Мультиагентного Рабочего Процесса: Автоматизированный Пайплайн Ревью PR

Вот как выглядит развёрнутая агентная система на практике:

```
[GitHub Webhook] → PR открыта
        ↓
[Агент-Оркестратор]
  ├─ Dispatch: Субагент Безопасности → сканирует diff на паттерны уязвимостей
  ├─ Dispatch: Субагент Покрытия → проверяет тест-файлы для изменённых модулей
  ├─ Dispatch: Субагент Соглашений → верифицирует именование, структуру, документацию
  └─ Dispatch: Субагент Резюме → читает описание PR + контекст diff
        ↓
[Агрегатор] → объединяет результаты, оценивает серьёзность
        ↓
[MCP GitHub] → публикует inline-комментарии + сводное ревью
```

Каждый субагент изолирован — он видит только необходимый ему контекст. Оркестратор управляет координацией и обрабатывает сбои, если какой-либо субагент выдаёт ошибку.

## Процесс

### Шаг 1 — Изучение Рабочего Процесса (1–2 часа)

Мы интервьюируем вас и вашу команду для картирования рабочего процесса, который вы хотите автоматизировать: входные данные, выходные данные, точки принятия решений, режимы сбоев и допустимые частоты ошибок. Мы определяем, какие части выигрывают от рассуждений ИИ, а какие — от детерминированного кода.

### Шаг 2 — Проектирование Архитектуры (1–3 дня)

Мы проектируем топологию агентов: сколько агентов, что делает каждый, как они коммуницируют, где устанавливаются ворота человеческого ревью и как система корректно завершает работу при сбое. Вы проверяете и одобряете дизайн до написания кода.

### Шаг 3 — Разработка и Тестирование (1–3 недели в зависимости от сложности)

Мы строим агентов итерационно, тестируя каждый компонент на реалистичных входных данных перед интеграцией. Вы получаете еженедельные демонстрации с работающей функциональностью на каждом этапе.

### Шаг 4 — Развёртывание и Передача

Мы развёртываем в вашем окружении, проводим end-to-end тесты и передаём кодовую базу с документацией, которую может поддерживать ваша команда. Мы обучаем минимум одного человека из вашей команды расширять и отлаживать систему.

## Часто Задаваемые Вопросы

**Насколько надёжны эти агенты в продакшене?**

Надёжность агентов зависит от дизайна задач. Мы встраиваем явную обработку неопределённости: агенты, которые не уверены, запрашивают уточнение, а не продолжают. Мы также строим тестовые стенды, чтобы вы могли измерить точность до развёртывания. Большинство клиентов нацелены на 80–90% автоматизации, с человеческим ревью для оставшихся случаев.

**На каком языке написаны агенты?**

Мы по умолчанию используем TypeScript за его типобезопасность и широкую экосистему. Python также доступен. SDK Claude Code поддерживает оба языка. Мы адаптируемся к предпочтительному языку вашей команды.

**Могут ли агенты выполняться по расписанию (ночное, еженедельное)?**

Да. Агенты могут запускаться по cron, webhook-ам, CI-событиям или изменениям файловой системы. Мы проектируем механизм запуска под вашу инфраструктуру.

**Как агенты обрабатывают конфиденциальный код или данные?**

Агенты работают с правами, которые вы им предоставляете — не больше. Конфиденциальные учётные данные передаются через переменные окружения. Мы проектируем агентов с минимально необходимым для задачи доступом. Все данные остаются в вашей инфраструктуре.

**Что если агент совершит ошибку?**

Мы строим агентов с возможностью отмены где возможно (черновые PR, не прямые слияния; staging-базы данных, не продакшен). Каждое деструктивное действие по умолчанию заблокировано за шагом подтверждения от человека.
