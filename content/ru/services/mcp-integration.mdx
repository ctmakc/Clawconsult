# Пользовательская Интеграция MCP-сервера

Claude Code мощный из коробки. С правильными MCP-серверами он становится чем-то совершенно другим — ИИ, который может запрашивать вашу продакшен-базу данных, создавать Notion-тикеты, вызывать ваши внутренние API и пушить код в GitHub, всё это из одного разговора.

**Model Context Protocol (MCP)** — это открытый стандарт, делающий это возможным. Он позволяет вам представить любой источник данных или инструмент как структурированный интерфейс, который Claude может вызывать во время сессии. Мы проектируем, строим и настраиваем пользовательские MCP-серверы, чтобы Claude Code мог достичь систем, важных для вашей команды.

## Что Мы Строим

### MCP-серверы для Баз Данных

Самая распространённая и высокоценная интеграция. Мы строим MCP-серверы, дающие Claude Code доступ на чтение (и опционально запись) к вашим базам данных с надлежащими мерами безопасности.

**MCP Postgres** — инспекция схемы, выполнение запросов только на чтение, оценки количества строк, анализ индексов. Claude может понять вашу модель данных и генерировать миграции, оптимизированные запросы и ORM-код, реально соответствующий вашей схеме.

**MCP SQLite** — идеально для локальных dev-баз данных, мобильных приложений и встроенной аналитики. Работает офлайн без сетевой конфигурации.

**MCP MySQL / MariaDB** — для команд, всё ещё работающих с MySQL-семейством баз данных.

**MCP MongoDB** — инспекция коллекций, выборка документов, помощь с агрегационными пайплайнами.

Все MCP-серверы баз данных поставляются с настраиваемыми правилами безопасности: какие схемы видны, разрешены ли записи, и лимиты таймаута запросов.

### MCP-серверы для Внутренних API

Если у вашей команды есть внутренние REST или GraphQL API — платформа данных, сервис feature-флагов, внутренний CMS, API деплоя — мы оборачиваем их в MCP-сервер, чтобы Claude мог вызывать их естественно во время разработки.

Пример: разработчик просит Claude «добавить новый feature flag `dark_mode` для мобильной beta-группы». Claude вызывает ваш API feature-флагов, создаёт флаг и подтверждает ID — браузер не нужен, копирование-вставка не нужна.

Мы обрабатываем аутентификацию (Bearer-токены, OAuth, API-ключи), валидацию запросов и разбор ответов. Результирующий MCP-сервер задокументирован, протестирован и поддерживаем.

### MCP Notion

Подключите Claude Code к вашему рабочему пространству Notion для:

- Создания и обновления проектных тикетов из комментариев в коде
- Чтения записей об архитектурных решениях и документов с требованиями во время кодовых сессий
- Автозаполнения спринт-бордов при коммите функций
- Генерации заметок совещаний из резюме сессий

Мы настраиваем права на уровне страниц, чтобы Claude видел только базы данных и страницы, релевантные инженерии.

### MCP GitHub / GitLab

Выходите за рамки того, что предлагает официальный GitHub CLI. Мы настраиваем MCP-сервер GitHub с:

- Ревью PR и публикацией inline-комментариев
- Созданием issues с правильными метками, вехами и исполнителями
- Поиском по репозиторию и кросс-репозиторной навигацией
- Проверкой статуса GitHub Actions

### Пользовательский MCP для REST API

Для любого другого HTTP API — внутреннего или стороннего — мы строим лёгкую MCP-обёртку. Типичные примеры:

- Stripe: проверить статус подписки, поискать записи клиентов во время сессий поддержки
- Jira: создавать и обновлять тикеты из контекста кода
- PagerDuty: инициировать и разрешать инциденты из runbook-скриптов
- Пользовательские аналитические API: получать метрики во время исследования производительности

## Сценарии Использования по Ролям

**Backend-инженеры** используют MCP-серверы баз данных для изучения схемы, отладки запросов и генерации миграций без переключения контекста.

**DevOps-инженеры** используют MCP-серверы API деплоя для проверки состояния инфраструктуры и запуска пайплайнов из той же сессии, где они пишут runbook-и.

**Full-stack-команды** используют MCP Notion + GitHub вместе, чтобы Claude мог отследить функцию от тикета до PR без выхода из терминала.

**Дата-сайентисты** используют MCP-серверы баз данных для получения образцов строк, инспекции распределений столбцов и генерации аналитического кода, откалиброванного на реальных данных.

## Часто Задаваемые Вопросы

**MCP-серверы запускаются на моей машине или в облаке?**

Поддерживаются оба варианта. Локальные MCP-серверы (транспорт stdio) работают на машине разработчика без сетевого воздействия. Хостируемые MCP-серверы (транспорт HTTP/SSE) могут работать на вашей инфраструктуре и использоваться командой совместно. Мы помогаем выбрать правильный транспорт для ваших требований безопасности.

**Можно ли добавить новые инструменты к существующему MCP-серверу позже?**

Да. MCP-серверы спроектированы для расширения. Мы строим их с чётким разделением между транспортом, маршрутизацией и обработчиками инструментов, поэтому добавить новый инструмент — просто. Мы можем сделать это за вас или задокументировать паттерн, чтобы ваша команда могла расширять самостоятельно.

**Как работает аутентификация? Мои учётные данные в безопасности?**

Учётные данные хранятся в переменных окружения на вашей машине или в менеджере секретов вашей команды — никогда не захардкоджены в исходнике MCP-сервера. Мы следуем принципу наименьших привилегий: MCP-сервер запрашивает только необходимые разрешения.

**Что если у моего API нет стабильной схемы?**

Мы встраиваем версионирование и корректную обработку ошибок, чтобы изменения API не крашили MCP-сервер. Для высокодинамичных API мы используем паттерн обобщённого HTTP-инструмента, к которому Claude может адаптироваться, вместо захардкоженных привязок методов.

**Можете ли вы строить MCP-серверы для API под NDA?**

Да. Мы подписываем NDA перед любым изучением внутреннего API. Весь результат работы принадлежит вам — мы не сохраняем код или схемы API после поставки.
