# Онбординг Команды на Claude Code

Раздать команде новый ИИ-инструмент и надеяться, что они сами разберутся — не работает. Разработчики возвращаются к старым привычкам, принятие стопорится, и прирост производительности никогда не реализуется. Эффективный онбординг меняет это.

Наша **программа командного онбординга Claude Code** даёт вашей инженерной команде контекст, конфигурацию и привычки, необходимые для продуктивного использования Claude Code с первого дня — не с третьего месяца.

## Что Включено

### Групповая Сессия Онбординга

Живая интерактивная сессия (удалённо или на месте в Оттаве), охватывающая:

- **Что такое Claude Code на самом деле** — модель, CLI, архитектура использования инструментов и чем он отличается от Copilot или ChatGPT
- **Живые демо реальных рабочих процессов** — ревью PR, написание тестов, отладка с субагентами, запросы к базам данных через MCP
- **Шаблоны промптов, которые работают** — как формулировать запросы, чтобы Claude давал полезные, корректные результаты; как корректировать курс, когда этого не происходит
- **Система skills** — как вызывать встроенные skills, как писать свои и когда использовать skills против свободного промптинга
- **Когда НЕ использовать Claude Code** — избегать режимов сбоев, которые расстраивают разработчиков и подрывают доверие к инструменту

Сессии длятся 2–3 часа для групп до 15 человек. Более крупные группы получают разбивку на несколько сессий. Все сессии записываются и передаются вам для асинхронного просмотра.

### Настройка CLAUDE.md по Репозиторию

Наиболее высокодейственная конфигурация для команды. Мы пишем файлы `CLAUDE.md` для каждого из ваших активных репозиториев, кодирующие:

- Контекст стека и фреймворка (больше не нужно объяснять ORM в каждой сессии)
- Соглашения о написании кода и применение руководства по стилю
- Паттерны тестирования и ожидания по покрытию
- Git-рабочий процесс (именование веток, формат сообщений коммитов, требования к PR)
- Архитектурные заметки и известные ограничения
- Ссылки на внутреннюю документацию, которую Claude должен использовать

Эти файлы коммитятся в систему контроля версий, чтобы каждый разработчик и каждый новый сотрудник автоматически получали одинаковый опыт работы с Claude.

### Библиотека Skills

Мы устанавливаем и настраиваем общую библиотеку skills, подобранную под типичные задачи вашей команды. Skills — это многоразовые, вызываемые рабочие процессы, которые Claude выполняет по требованию. Мы настраиваем:

- `commit-commands` — стандартизированный коммит + создание PR по соглашениям вашей команды
- `pr-review` — структурированное ревью PR с проверками безопасности, покрытия и соглашений
- `systematic-debugging` — управляемый протокол расследования ошибок
- `test-driven-development` — цикл применения TDD
- Доменно-специфические skills для вашего стека (skills деплоя Next.js, skills миграции Django и т.д.)

### Настройка Хуков

Хуки автоматизируют предохранители, необходимые вашей команде. Мы настраиваем:

- Pre-commit хуки, запускающие линтер и тест-сьют перед коммитом Claude
- Post-edit хуки автоформатирования
- Хуки безопасности, приостанавливающие работу перед деструктивными операциями
- Хуки уведомлений для долгих задач агентов

Хуки настраиваются на уровне проекта и коммитятся вместе с файлами CLAUDE.md.

### 30-дневное Сопровождение

После сессии у вашей команды появятся вопросы, которые не возникли, пока они не попробовали делать реальную работу. Наше 30-дневное сопровождение включает:

- Асинхронные Q&A через общий Slack-канал или email-цепочку
- Один дополнительный групповой звонок (30 минут) на отметке двух недель
- Обновления файлов CLAUDE.md и skills по мере выявления пробелов
- Эскалационный путь для всего, что требует более глубокой сессии настройки

## Форматы

**Удалённо (стандарт)** — Zoom или Google Meet. Подходит для распределённых команд. Все материалы доставляются цифровым способом.

**На месте в Оттаве** — мы приезжаем в ваш офис на сессию. Идеально для команд на одном месте, желающих полноценного воркшоп-опыта. Транспортные расходы применяются для мест за пределами Оттавы.

**Гибридно** — групповая сессия удалённо, дополнительные конфигурационные сессии на месте.

## Часто Задаваемые Вопросы

**Насколько технической получается сессия онбординга?**

Мы калибруем сессию под уровень вашей команды во время предварительного звонка с организатором. Команда опытных backend-инженеров получает иную глубину, чем смешанная команда с джуниорами. Мы всегда проводим живые демо, а не слайды.

**Нужно ли разработчикам что-то установить перед сессией?**

Да. Мы отправляем предварительный чеклист: Claude Code установлен, ключ Anthropic API настроен, и подготовлен один тестовый репозиторий. Чеклист занимает около 20 минут. Мы отправляем его за неделю до сессии.

**Можем ли мы записать сессию для разработчиков, которые не могут присутствовать?**

Да, все сессии записываются по умолчанию. Мы доставляем запись в течение 24 часов. Разработчики, присоединяющиеся асинхронно, могут задавать вопросы через канал поддержки сопровождения.

**Что если наша команда использует несколько технологических стеков?**

Мы пишем отдельные файлы CLAUDE.md для каждого репозитория. Если у вас Python-бэкенд и React-фронтенд — каждый получает адаптированный файл. Команды с несколькими стеками — обычное дело, это не проблема.

**Как поддерживать файлы CLAUDE.md после онбординга?**

Мы документируем соглашения, которых придерживались, чтобы ваша команда могла обновлять файлы самостоятельно. Типичные триггеры для обновлений: добавление нового фреймворка, изменение стратегии тестирования, подключение нового репозитория. Мы рекомендуем ежеквартальный обзор CLAUDE.md — мы можем делать это как лёгкий асинхронный retainer.
