# Шаблон промпта для запуска проекта в Claude Code

Начало нового проекта с Claude Code из пустой директории нередко даёт непоследовательные результаты — Claude принимает разумные, но произвольные решения о структуре, инструментах и соглашениях, которые могут не соответствовать вашему стилю работы.

Этот шаблон предоставляет структурированный стартовый промпт, который принуждает принять важные решения заранее, документирует их в `CLAUDE.md` и приводит к первому рабочему коммиту с правильным фундаментом.

Используйте его в начале любого greenfield-проекта или при первичном подключении существующего проекта к Claude Code.

---

## Когда использовать этот шаблон

- **Новый greenfield-проект** — вы начинаете с `mkdir мой-проект`
- **Существующий проект, первая сессия Claude Code** — Claude нужно понять вашу текущую конфигурацию, прежде чем вносить изменения
- **Возобновление после долгого перерыва** — переориентирование Claude на текущее состояние проекта
- **Передача коллеге** — он открывает проект и выполняет этот промпт для быстрой ориентации

```
## Последовательность настройки

Выполнить эти шаги по порядку. После каждого шага сделать паузу и подтвердить сделанное, прежде чем переходить к следующему.

### Шаг 1 — Создать scaffold проекта

Инициализировать проект с указанным менеджером пакетов и фреймворком. Создать структуру директорий. Установить зависимости. Не писать никакой функциональный код пока.

Ожидаемый результат: рабочий scaffold, где `[команда dev]` запускается без ошибок.

### Шаг 2 — Настроить инструменты

Настроить:
- Линтинг: ESLint (или аналог) с дефолтами для языка проекта
- Форматирование: Prettier (или аналог) — конфиг закоммичен, не просто установлен
- Проверка типов: tsc --strict (или аналог)
- Git: инициализировать репозиторий, если ещё нет, создать .gitignore

Ожидаемый результат: `[команда lint]` и `[команда typecheck]` выполняются без ошибок на пустом scaffold.

### Шаг 3 — Написать CLAUDE.md

Создать `CLAUDE.md` в корне проекта с документацией:
- Точный стек (с версиями)
- Структура директорий и что где находится
- Каждая команда разработки (start, test, lint, build, typecheck, migrate)
- Соглашения по коду, которые мы будем использовать в этом проекте
- Все защищённые файлы или директории
- Словарь домена для этого проекта

CLAUDE.md должен быть достаточно полным, чтобы новая сессия Claude Code, начав с него, могла работать над кодовой базой без дополнительных объяснений.

### Шаг 4 — Первая рабочая фича

Реализовать минимальную версию этой фичи, чтобы доказать, что scaffold работает от начала до конца:

[ОПИСАТЬ ПЕРВУЮ ФИЧУ — напр.: "Эндпоинт /health, возвращающий { status: 'ok', timestamp: ISO8601 }" или "CLI-команда `init`, создающая файл конфигурации в текущей директории"]

Эта фича должна:
- Быть реализована в правильном месте согласно структуре в CLAUDE.md
- Иметь хотя бы один проходящий тест
- Проходить lint и typecheck

### Шаг 5 — Первый коммит

После завершения шага 4 и прохождения тестов:
- Застейджировать все файлы
- Создать коммит с сообщением: `feat: начальный scaffold проекта с [НАЗВАНИЕ ПЕРВОЙ ФИЧИ]`
- Показать мне git log и вывод тестов, чтобы я мог убедиться, что всё в порядке

---

После выполнения всех пяти шагов дайте краткое резюме:
- Что было настроено
- Где находятся ключевые файлы
- Какая следующая задача разработки была бы естественной
- Любые решения, которые вы приняли и о которых я должен знать
```

## Как адаптировать шаблон

### Для существующего проекта

Замените шаги 1–2 на:

```
### Шаг 1 — Ориентироваться в проекте

Прочитать существующую структуру проекта. Запустить существующие тесты. Проверить, что lint и typecheck проходят.
Доложить:
- Что делает проект (вывод из кода/README)
- Текущий стек с версиями
- Любые падающие тесты или ошибки линтера
- Файлы, которые выглядят автогенерированными или защищёнными

Пока не вносить никаких изменений.
```

Затем продолжить с шага 3 (написать CLAUDE.md на основе найденного).

### Для MVP-продукта в одиночку

Сократите шаг 4 до одного сквозного happy path:

```
### Шаг 4 — Smoke test путь

Реализовать ровно столько, чтобы можно было вручную пройти один сквозной пользовательский флоу:
[описать флоу]

Тесты на этом этапе не требуются. Мы добавим их в следующей сессии.
```

### Для командного проекта

Добавьте к шагу 3:

```
В CLAUDE.md включить раздел "Команда" с:
- Кто отвечает за backend / БД / инфраструктуру / frontend
- Как проверяются PR (1 ревьюер? 2?)
- Соглашение по именованию веток
- Что должен пройти CI перед мержем
```

## Что делать после запуска

После выполнения стартового промпта и создания первого коммита:

1. **Прочитайте CLAUDE.md, который написал Claude.** Исправьте всё неверное. Это документ, который будут использовать все последующие сессии.
2. **Добавьте реальный словарь домена.** Первая сессия производит общие термины; замените их на реальную бизнес-терминологию вашего проекта.
3. **Настройте хуки.** Используйте [шаблон конфигурации хуков](/templates/hooks-config) для немедленного добавления автоформатирования и резервного копирования сессии.
4. **Напишите первую реальную задачу как точный промпт.** Используйте соглашения из CLAUDE.md, чтобы написать промпт, называющий файлы, определяющий критерии приёмки и указывающий ограничения. См. [эффективные практики с Claude Code](/skills/effective-claude-code).

## Типичные ошибки

**Пропустить шаг 3 (CLAUDE.md).** Это самая частая ошибка. Запуск мало что даёт без создания CLAUDE.md — каждая последующая сессия будет стартовать с нуля.

**Выбрать слишком большую «первую фичу» для шага 4.** Первая фича должна быть минимальной вещью, доказывающей, что scaffold работает сквозным образом. Если первая фича занимает более 30 минут на реализацию — она слишком большая. Выберите что-то тривиальное.

**Не проверить решения по стеку, принятые Claude.** Claude сделает разумные выборы для всего, что вы оставили неуказанным. Проверьте их в созданном CLAUDE.md — исправить сейчас проще, чем после 20 коммитов.

**Запускать стартовый промпт в непустой директории.** Начинайте с чистого `mkdir мой-проект && cd мой-проект`. Запуск в директории с существующими файлами ломает шаг создания scaffold.

## Справочник переменных шаблона

| Переменная | Что сюда вписать |
|---|---|
| `[НАЗВАНИЕ_ПРОЕКТА]` | Название проекта — используется в сообщениях коммитов и CLAUDE.md |
| `[ОДНО ПРЕДЛОЖЕНИЕ]` | Что делает продукт и кто им пользуется — максимум 15 слов |
| `[ОГРАНИЧЕНИЕ N]` | Жёсткие ограничения, которые должен соблюдать Claude — не предпочтения, а реальные ограничения |
| `[команда dev]` | Команда для запуска dev-сервера (напр.: `pnpm dev`) |
| `[команда lint]` | Команда линтинга (напр.: `pnpm lint`) |
| `[ОПИСАТЬ ПЕРВУЮ ФИЧУ]` | Минимальная сквозная фича, доказывающая работоспособность scaffold |
| `[НАЗВАНИЕ ПЕРВОЙ ФИЧИ]` | Короткое название для сообщения коммита (напр.: `эндпоинт health`) |
