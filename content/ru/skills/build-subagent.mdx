# Как создавать сабагентов в Claude Code

Сабагенты — это независимые экземпляры Claude, которые оркестратор-агент запускает для выполнения конкретных задач. У них собственные контекстные окна, собственный доступ к инструментам, и они возвращают результаты обратно родительскому агенту. Claude Code предоставляет эту возможность через **инструмент Agent**, доступный модели во время агентной сессии.

В этом руководстве объясняется, что такое сабагенты, когда их использовать, как писать для них промпты, как запускать их параллельно и как избежать наиболее распространённых ошибок.

---

## Что такое сабагенты

Когда Claude Code выполняет задачу, он работает в рамках одного контекстного окна — ограниченного разговора между вами, моделью и её вызовами инструментов. Для большинства задач этого достаточно. Для сложных задач это создаёт две проблемы:

1. **Истощение контекста.** Длинная задача заполняет контекстное окно. Когда окно заполнено, модель больше не видит более ранние части задачи, и производительность снижается.
2. **Связанность.** Когда одна часть задачи выходит из строя или производит шумный вывод, это загрязняет контекст для последующих частей.

Сабагент решает обе проблемы. Это свежий экземпляр Claude — собственное контекстное окно, начинающееся с нуля, — который получает только то, что ему нужно, через промпт. Когда сабагент завершает работу, он возвращает результат оркестратору. Оркестратор видит результат, а не полный след того, как сабагент к нему пришёл.

Сабагенты не всегда быстрее. Они несут накладные расходы: каждый делает API-вызовы, обрабатывает промпт и может выполнять собственные вызовы инструментов. Преимущество — изоляция и параллелизм, а не сырая скорость.

---

## Когда использовать сабагентов

Используйте сабагентов, когда ваша задача имеет явно разделимые компоненты, которые либо:

- **Могут выполняться параллельно** — две независимые подзадачи, которым не нужен вывод друг друга для начала работы.
- **Нуждаются в защите контекста** — вы не хотите, чтобы вывод одной подзадачи загрязнял рассуждение оркестратора о другой.
- **Достаточно велики** — задача сабагента должна требовать хотя бы нескольких вызовов инструментов, чтобы оправдать накладные расходы.

**Хорошие кандидаты:**
- Запустить аудит безопасности кодовой базы одновременно с тестовым набором.
- Исследовать документацию библиотеки, пока другой агент читает существующую реализацию.
- Обработать 10 файлов независимо, по одному сабагенту на файл.
- Сгенерировать черновик, затем запустить отдельный агент ревью для его критики.

**Плохие кандидаты:**
- Задача в две строки, которую быстрее сделать inline.
- Задачи, которым нужно текущее состояние оркестратора (память, незавершённые правки) для продолжения.
- Всё, что требует тесного диалога с пользователем — сабагенты не могут обращаться к пользователю напрямую.

## Инструмент Agent — параметры

Инструмент Agent вызывается моделью (не вами напрямую). Когда вы пишете CLAUDE.md или системный промпт, который просит Claude использовать сабагентов, вы инструктируете оркестратор генерировать вызовы инструмента Agent. Понимание параметров помогает писать лучшие промпты оркестрации.

```
Agent(
  description: string        // Краткая метка — отображается в UI, используется в логах
  prompt: string             // Полное описание задачи для сабагента
  subagent_type?: string     // "general" (по умолчанию) | имя модели для переопределения
  run_in_background?: bool   // Запустить без ожидания; оркестратор продолжает сразу
  isolation?: string         // "none" (по умолчанию) | "worktree"
)
```

**`description`** — Держите кратким и читаемым: `"Security audit of auth module"`, `"Test suite runner"`. Это метка, которую вы увидите в UI Claude Code при работе нескольких агентов.

**`prompt`** — Это весь мир, который видит сабагент. Пишите его так, будто передаёте задачу человеку, который ничего не знает о вашей текущей сессии. Смотрите раздел о дизайне промптов ниже.

**`subagent_type`** — Позволяет направить задачи к другой модели. Используйте `claude-opus-4-5` для задач со сложными рассуждениями, `claude-haiku-4-5` для высокообъёмных дешёвых задач. Если не указано, сабагент использует ту же модель, что и оркестратор.

**`run_in_background`** — Если `true`, оркестратор не ждёт завершения сабагента. Оркестратор переходит к следующему шагу сразу. Полезно для fire-and-forget задач вроде логирования или прогрева кеша; менее полезно, когда оркестратору нужен результат для продолжения.

**`isolation`** — `"worktree"` создаёт отдельную копию git-репозитория в новом worktree перед запуском сабагента. Сабагент может редактировать файлы, не затрагивая рабочее дерево оркестратора. Результаты объединяются обратно, когда сабагент завершает работу. Используйте это, когда сабагенты будут редактировать файлы одновременно.

## Написание хороших промптов для сабагентов

Наиболее распространённый провал сабагентов — недостаточно детализированный промпт. Поскольку сабагент начинает без памяти о родительской сессии, он не может выводить из контекста то, что кажется очевидным оркестратору.

### Чек-лист для каждого промпта сабагента

**1. Явно сформулируйте цель.**
Не пишите «проверь модуль auth». Пишите «Проверь файл `src/auth/jwt.ts` на наличие уязвимостей безопасности. Сосредоточься на обработке срока действия токенов, верификации подписи и управлении секретами. Верни markdown-список находок с уровнем серьёзности (high/medium/low) для каждой.»

**2. Передавайте необходимый контекст inline.**
Если сабагенту нужно знать об ограничении, включите его:

```
You are reviewing a codebase that uses Express 4.x with JWT authentication.
The API key is stored in the environment variable ANTHROPIC_API_KEY.
Do NOT read or log the contents of .env files.
```

**3. Укажите формат вывода.**
Оркестратор будет разбирать или суммировать возвращаемое значение сабагента. Если вам нужен структурированный вывод, скажите об этом:

```
Return your findings as JSON with this shape:
{ "severity": "high" | "medium" | "low", "file": string, "line": number, "description": string }[]
```

**4. Скажите сабагенту, чего НЕ делать.**
Сабагенты будут пытаться выполнить задачи тщательно. Если есть границы — файлы для пропуска, действия для избегания — укажите их явно:

```
Do NOT make any file edits. Read-only analysis only.
Do NOT install any packages.
Limit your search to the src/ directory.
```

**5. Включите условие остановки.**
Сабагенты без чёткого критерия завершения могут излишне исследовать:

```
Stop after you have analyzed all files matching src/auth/**/*.ts.
Do not expand the search to other directories.
```

## Передача контекста

Сабагенты не могут получить доступ к памяти оркестратора, открытым файлам или результатам предыдущих вызовов инструментов. Каждый фрагмент информации, который нужен сабагенту, должен быть в его промпте.

### Паттерны передачи контекста

**Передавать пути к файлам, а не содержимое файлов (для больших файлов):**

```
Read the file at /home/user/project/src/auth/jwt.ts and audit it for vulnerabilities.
```

Сабагент использует инструмент Read, чтобы самостоятельно получить файл. Это держит промпт кратким.

**Передавать небольшое содержимое inline (для коротких фрагментов):**

```
Here is the relevant function. Review it for SQL injection risks:

```typescript
async function getUserById(id: string) {
  return db.query(`SELECT * FROM users WHERE id = '${id}'`);
}
```
```

**Передавать результаты предыдущих шагов как структурированные данные:**

Если оркестратор запустил тестовый набор и получил список упавших тестов, передайте этот список:

```
The following tests are failing. Diagnose the root cause for each and propose a fix.
Do not run the tests — only analyze the code.

Failing tests:
- UserController > createUser > should validate email format
- AuthService > login > should reject expired tokens
- ...
```

## Параллельный запуск

Чтобы запустить несколько сабагентов одновременно, оркестратор генерирует несколько вызовов инструмента Agent в одном ответе. Claude Code выполняет их параллельно и ждёт завершения всех перед продолжением.

Вот как инструктировать оркестратор делать это в вашем системном промпте или CLAUDE.md:

```markdown
## Orchestration Instructions

When facing tasks with independent components, spawn multiple subagents in a single
response. For example, if asked to "audit security and run tests":

1. Spawn a subagent to audit src/auth/ for security vulnerabilities.
2. In the same response, spawn a second subagent to run `npm test` and collect failures.
3. Wait for both to complete, then synthesize their reports.

Never run these sequentially when they can run in parallel.
```

Оркестратор сгенерирует примерно следующее (концептуально):

```
Agent(description="Security audit", prompt="Audit src/auth/ for vulnerabilities...")
Agent(description="Test runner", prompt="Run npm test and report all failures...")
```

Оба запускаются одновременно. Оркестратор получает оба результата, затем рассуждает о них вместе.

## Фоновые агенты

Установка `run_in_background: true` говорит оркестратору не ждать сабагента. Оркестратор немедленно переходит дальше. Сабагент завершается асинхронно, и результат доставляется оркестратору позже.

Используйте для:
- Уведомлений (отправка сообщения в Slack, запись в лог)
- Прогрева кеша или предварительных вычислений, которые оркестратору не нужны немедленно
- Длительных задач, когда вы хотите, чтобы основной поток продолжал работу

Избегайте, когда следующий шаг оркестратора зависит от вывода сабагента — результат не будет доступен вовремя.

---

## Режимы изоляции

**`isolation: "none"` (по умолчанию)** — Сабагент работает в том же git-рабочем дереве, что и оркестратор. Правки файлов сабагентом немедленно видны оркестратору и наоборот. Подходит для read-only сабагентов или когда только один сабагент редактирует файлы одновременно.

**`isolation: "worktree"`** — Claude Code создаёт новый git-worktree (параллельный чекаут того же репозитория) для сабагента. Правки сабагента происходят в этом worktree и не затрагивают рабочую директорию оркестратора. Когда сабагент завершает работу, его изменения можно объединить обратно или отбросить.

Используйте изоляцию `worktree`, когда:
- Несколько сабагентов будут редактировать одни и те же файлы одновременно.
- Вы хотите посмотреть, что сабагент сделал бы, без обязательства к этому.
- Сабагент может делать деструктивные правки, которые вы хотите иметь возможность отбросить.

---

## Чтение результатов сабагентов

Финальный ответ сабагента (то, что он выводит в конце сессии) возвращается оркестратору как результат вызова инструмента Agent. Оркестратор может затем:

- Суммировать несколько результатов для пользователя
- Использовать результаты как входные данные для следующего шага
- Решить, повторить ли попытку или эскалировать на основе результата

Разрабатывайте промпты сабагентов для производства чистого, разбираемого результата. Если сабагент возвращает стену текста с рассуждениями, оркестратор вынужден проделывать дополнительную работу для извлечения сигнала.

## Реальный пример: исследование и код-ревью параллельно

Вот проработанный пример оркестратора, запускающего двух сабагентов параллельно: один исследует API библиотеки, другой ревьюит существующую реализацию.

**Промпт оркестратора (в CLAUDE.md или системном промпте):**

```markdown
You are a senior engineering assistant. When asked to "upgrade a dependency," do the following:

1. In a single response, spawn two subagents simultaneously:

   Subagent A — Research:
   Read the CHANGELOG and README of the new library version in node_modules.
   Return a markdown summary of breaking changes and new APIs relevant to our codebase.

   Subagent B — Review current usage:
   Search the src/ directory for all imports and calls to the old library.
   Return a list of every usage location with file path and line number.

2. After both subagents return, synthesize their findings:
   - Map each breaking change to the affected usage locations.
   - Propose a specific code change for each affected file.

3. Only then begin making edits.
```

С такой настройкой исследование и сканирование использований происходят параллельно. Оркестратор синтезирует, когда оба завершены, затем приступает к работе с полной картиной — вместо того чтобы обнаружить критическое изменение API в середине редактирования.

## Типичные ошибки

**Промпт сабагента ссылается на «сказанное выше» или «как обсуждалось».**
У сабагента нет памяти о разговоре выше. Каждая ссылка должна быть явной.

**Оркестратор ждёт результата фонового агента.**
Если `run_in_background: true`, результат недоступен на следующем шаге. Используйте фоновых агентов только когда оркестратор действительно не нуждается в выводе.

**Параллельные агенты редактируют один файл без изоляции worktree.**
Два сабагента, пишущих в один файл, испортят работу друг друга. Либо сериализуйте их выполнение, либо используйте `isolation: "worktree"` с последующим объединением.

**Промпт сабагента слишком открыт.**
«Проверь кодовую базу на проблемы» заставит сабагент потратить всё контекстное окно на широкое сканирование. Ограничьте задачу: «Проверь `src/api/routes/users.ts` на проблемы с валидацией входных данных.»

**Запуск сабагентов для тривиальных задач.**
Каждый вызов сабагента несёт задержку и накладные расходы. Задача, занимающая два вызова инструментов inline, не выиграет от делегирования сабагенту.
