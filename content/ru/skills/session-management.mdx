# Управление сессиями Claude Code: контекст, компактизация и непрерывность

Каждая сессия Claude Code работает в пределах контекстного окна — конечного объёма текста, о котором Claude может активно рассуждать одновременно. Понимание того, как работают сессии, как управляется контекст и как структурировать длительную работу — это разница между плавными многодневными проектами и утомительными, повторяющимися разговорами.

## Как работают сессии Claude Code

### Контекстное окно

Claude Code использует большое контекстное окно (точный размер зависит от модели — у Sonnet 4.6 и Opus 4.x окна по 200K токенов), но оно конечно. Каждый прочитанный файл, каждый результат инструмента, каждый обмен в разговоре потребляет контекстные токены.

**Что быстро потребляет контекст:**
- Чтение больших файлов (500-строчный TypeScript-файл ≈ 2000 токенов)
- Большой вывод команд (запуск `npm run build` с множеством предупреждений)
- Долгие диалоги на сложные темы
- Многократное чтение одних и тех же файлов
- Многословные результаты bash-команд

**Что остаётся лёгким:**
- Короткие, целевые вопросы
- Чтение только конкретных нужных строк (с использованием `offset` и `limit` в Read)
- Лаконичные bash-команды с сфокусированным выводом

### Сжатие контекста

Когда разговор приближается к пределу контекста, Claude Code автоматически сжимает предыдущие сообщения в краткое изложение. Это сжатие сохраняет существенные факты и решения, но теряет точные формулировки. Система уведомляет вас о сжатии заметкой в разговоре.

**Что сжатие сохраняет:**
- Что было сделано
- Какие решения были приняты
- Какие файлы были созданы или изменены
- Какие ошибки встретились и как были решены

**Что сжатие может потерять:**
- Точные формулировки более ранних сообщений
- Детальные рассуждения из начала сессии
- Конкретное содержимое файлов, которые читались, но не были задействованы в действиях

## Команда /compact

`/compact` запускает ручное сжатие контекста до того, как система сделает это автоматически. Используйте её проактивно — до того как вы потеряли управление сессией, а не после.

### Когда использовать /compact

**Используйте /compact, когда:**
- Вы закончили логически цельный блок работы (фичу, набор правок файлов, отладочную сессию)
- Вы собираетесь начать новую, самостоятельную задачу в той же сессии
- Вы замечаете, что сессия становится «тяжёлой» — ответы начинают дрейфовать или терять контекст
- Вы провели в сессии 2+ часа и впереди ещё значительная работа

**Не используйте /compact, когда:**
- Вы находитесь в середине сложной многошаговой операции, где потеря точного промежуточного состояния создаст проблемы
- Claude только что прочитал большой файл, на который вам нужно будет ссылаться на следующем шаге
- Вы в отладочном цикле, которому требуется полная история ошибок в активном состоянии

### Что делает /compact

`/compact` просит Claude суммировать текущий разговор в компактное представление, затем продолжить с этого резюме. Опционально можно передать фокус:

```
/compact focus on the authentication module changes we made
```

Без фокуса Claude сам решает, что важнее всего сохранить. С фокусом он приоритизирует эти элементы в резюме.

После `/compact` сессия продолжается: Claude осведомлён о том, что произошло (через резюме), но без полной истории разговора в активном контексте.

## Структурирование долгосрочных проектов

### Границы сессий и непрерывность

Сессии не сохраняются между процессами Claude Code. Когда вы выходите и перезапускаете, Claude начинает с чистого контекста. Это сделано намеренно — чтобы предотвратить загрязнение новой работы устаревшими предположениями.

**Как поддерживать непрерывность между сессиями:**

**1. CLAUDE.md — постоянная память вашего проекта**

`CLAUDE.md` в корне проекта всегда загружается в контекст Claude при запуске сессии в этой директории. Используйте его для документирования:
- Что представляет собой проект и что вы создаёте
- Текущий статус (что сделано, что в процессе, что следующее)
- Ключевые архитектурные решения и их причины
- То, что Claude должен знать, но не может вывести из кода
- Активные блокеры или открытые вопросы

Обновляйте CLAUDE.md в конце каждой сессии. В следующей сессии Claude прочитает его и получит актуальный контекст.

```markdown
# MyApp CLAUDE.md

## Status (2026-05-15)
- Auth module: COMPLETE ✅
- Dashboard: IN PROGRESS — data fetching works, rendering broken on mobile
- Payment integration: NOT STARTED

## Active issues
- Dashboard: `useInfiniteQuery` returns undefined on first render (SSR hydration mismatch)
  - Tried: disabling SSR, using Suspense, setting initialData
  - Not tried: manual cache seed on server, separate client component

## Key decisions
- Using Zustand not Redux (simpler for this scope)
- Supabase for auth, not NextAuth (already have existing Supabase project)
- Mobile-first layout breakpoints (375px base)
```

**2. Отслеживание задач**

Используйте инструменты TaskCreate/TaskUpdate во время сессий для ведения списка задач. Задачи сохраняются и могут быть просмотрены в начале новой сессии для восстановления контекста.

**3. Git как память сессий**

Коммитьте часто и пишите содержательные сообщения коммитов. Когда вы начинаете новую сессию, `git log --oneline -20` даёт Claude чёткую картину недавнего прогресса без перечитывания всего кода.

```
git log --oneline -20
# 3ae2e33 fix: dashboard infinite scroll bug on Safari
# 2a1b4c5 feat: user profile page with avatar upload
# 9f8d2e1 fix: auth token refresh race condition
```

**4. Статусные документы**

Для больших проектов ведите `PROGRESS.md` или `STATUS.md`, который вы обновляете в конце каждой сессии:

```markdown
# Auth module — complete
# Dashboard — data layer done; UI bug active (see CLAUDE.md)
# Payments — not started; Stripe account needed first
```

## Типичные ошибки в управлении сессиями

### Повторное чтение одних и тех же файлов

Если Claude читает `app/page.tsx` пять раз за одну сессию, потому что ему нужно проверять разные вещи, — это 5-кратные токенные затраты. Вместо этого:

**Лучший паттерн:** Прочитать файл один раз в начале задачи, выполнить всю работу, которая его требует, затем перейти к следующей задаче.

**Ещё лучше:** Когда вы знаете, что сессия будет связана с большим файлом, прочитайте его заранее и дайте Claude чёткое резюме того, что вам нужно от него. «Этот файл управляет нашей маршрутизацией — мы будем добавлять новый маршрут в строке 87 и обновлять middleware в строке 134.»

### Просьба к Claude суммировать без направления

`/compact` без фокуса создаёт обобщённое резюме. Если ваша сессия была на 80% отладкой неочевидного бага и на 20% написанием документации, компакт обработает их как равнозначные. Давайте Claude направление:

```
/compact focus on the routing middleware debugging — specifically the CORS header issue and the solution we arrived at
```

### Начало новых задач без сброса контекста

Если вы заканчиваете фичу и немедленно переключаетесь на другой модуль без компактизации, Claude несёт полный вес предыдущей задачи. Пять минут `/compact` и чёткий новый промпт дают более качественную работу, чем просьба к Claude переключить контекст с уже полностью загруженной сессией.

### Не обновлять CLAUDE.md

Наиболее распространённый сбой непрерывности сессий: значительная работа выполнена, решения приняты, затем сессия завершается без обновления CLAUDE.md. Следующая сессия начинается без этого контекста, и Claude повторно обнаруживает ту же информацию или принимает несогласованные решения.

Сделайте обновление CLAUDE.md частью завершения сессии: «Прежде чем закончим, обнови CLAUDE.md с тем, что мы выполнили и что следующее.»

## Управление бюджетом контекста

Думайте о контекстных токенах как о бюджете, который вы хотите тратить мудро, а не о лимите, которого стараетесь не достигать.

**Высокоценные траты токенов:**
- Чтение файлов, которые вы реально будете редактировать
- Запуск команд, вывод которых влияет на следующее решение
- Обсуждение архитектуры перед её реализацией

**Низкоценные траты токенов:**
- Чтение файлов из любопытства (используйте grep или целевой поиск вместо этого)
- Запуск команд, вывод которых вы могли бы предсказать
- Длинный диалог по уже принятым решениям

**Управление бюджетом контекста на практике:**

Для реализации сложной фичи:
1. Начало: прочитать CLAUDE.md (контекст проекта), запустить `git log --oneline -10` (недавняя история)
2. Исследование: целевое чтение релевантных файлов, целевой grep для паттернов
3. Планирование: краткое обсуждение подхода к реализации
4. Реализация: редактирование файлов, запуск целевых тестов
5. Валидация: запуск полного тестового набора один раз, исправление проблем
6. Завершение: обновление CLAUDE.md, коммит, `/compact` или завершение сессии

Этот паттерн держит контекстное окно сфокусированным на активной работе, а не на накопленном исследовании.

## Многосессионные проекты

Для проектов, охватывающих дни или недели:

**Ритуал начала сессии:**
1. Claude читает CLAUDE.md автоматически (держите его обновлённым!)
2. Запросить текущую задачу: «Прочитай CLAUDE.md, затем скажи мне, над чем нам следует работать дальше исходя из текущего статуса.»
3. Краткий обзор `git log`

**Ритуал завершения сессии:**
1. Закоммитить все изменения с содержательным сообщением
2. Обновить CLAUDE.md с текущим статусом
3. Написать абзац о том, что вы хотите знать в следующей сессии: текущие блокеры, активные решения, следующие шаги

**Контекст между сессиями:** Ведите `DECISIONS.md` для архитектурных решений, которые не подходят для CLAUDE.md, но которые Claude мог бы переосмысливать без документации:

```markdown
# 2026-05-12: Chose RSA-OAEP over ECDH for key exchange
Reason: existing PKI infrastructure uses RSA; switching to ECDH would require migrating all existing key pairs.
Considered: ECDH (better performance), RSA-OAEP (compatible with existing infra) → chose compat.
```

## Параллельные сессии и worktrees

Claude Code поддерживает одновременный запуск нескольких независимых сессий с использованием git-worktrees. Каждый worktree — это изолированная копия репозитория на отдельной ветке.

```bash
# Создать worktree для параллельной фичи
git worktree add ../myapp-auth-feature auth/feature-oauth

# Открыть новый терминал, запустить Claude Code в worktree
cd ../myapp-auth-feature
claude
```

Каждая сессия Claude Code в каждом worktree независима — они не делят контекст. Это полезно для:
- Параллельной разработки фич без конфликтов веток
- Запуска долгоживущего агента в одном worktree, пока вы работаете интерактивно в другом
- Экспериментирования с рискованными изменениями без влияния на основное рабочее пространство

Используйте `ExitWorktree` для очистки по завершении (или `git worktree remove` вручную).
