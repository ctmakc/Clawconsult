# Claude Code для DevOps

DevOps-работа монотонна, высокоответственна и нередко плохо задокументирована. Написать двенадцатый вариант Dockerfile для нового сервиса, отлаживать нестабильный GitHub Actions пайплайн в 23:00 или переводить устный runbook в структурированный YAML — эти задачи не требуют глубокой креативности, но требуют глубокого контекста. Claude Code обеспечивает этот контекст.

На этой странице рассказывается, как DevOps-инженеры используют Claude Code в реальных рабочих процессах: что он делает хорошо, какие промпты работают и как подключить его к инфраструктуре через MCP-серверы.

## Основные Сценарии Использования

### Dockerfile и Конфигурация Контейнеров

Claude Code читает исходники вашего приложения — `package.json`, `requirements.txt`, `go.mod`, что угодно — и генерирует готовый к продакшену Dockerfile с многоэтапными сборками, правильной настройкой пользователя без root, оптимизацией кэша сборки и конфигурацией health check.

**Чем это лучше шаблона**: он смотрит на ваши реальные зависимости, определяет, какие из них требуют нативных инструментов сборки, и обрабатывает сложность (компиляция нативных Node-модулей, компромиссы Alpine vs. Debian, установка нужных системных пакетов), а не даёт вам общую отправную точку, которая работает наполовину.

Типичный шаблон промпта:

```
Просмотри приложение в ./src/ и сгенерируй готовый к продакшену Dockerfile.
Используй многоэтапную сборку, запускай от пользователя без root и оптимизируй 
кэширование слоёв для нашего менеджера пакетов. Добавь директиву HEALTHCHECK.
```

### Генерация YAML Kubernetes

Создание корректных манифестов Kubernetes с нуля — утомительное и подверженное ошибкам занятие. Claude Code генерирует Deployment, Service, Ingress, ConfigMap, HorizontalPodAutoscaler и PodDisruptionBudget с правильной структурой и разумными значениями по умолчанию.

Что важнее — он рассуждает о ваших ограничениях: если вы сообщите, что работаете на кластере из 3 узлов по 4 Гб каждый, он установит соответствующие запросы и лимиты ресурсов, а не оставит эти поля пустыми.

```
Сгенерируй Kubernetes Deployment для сервиса auth.
Он запускает 3 реплики, требует 256Mi RAM и 200m CPU, подключается к Postgres через 
$DATABASE_URL (из секрета) и выставляет порт 8080.
Добавь liveness probe на /healthz.
```

### Отладка CI/CD Пайплайнов

Вставьте в сессию упавший лог GitHub Actions или GitLab CI. Claude Code определяет ошибку, объясняет, почему она произошла, и предлагает исправление — обычно за секунды для типичных паттернов сбоев: ошибки прав доступа, отсутствующие ключи кэша, проблемы слоёв Docker или инъекция секретов.

Он также помогает писать новые пайплайны: опишите нужный рабочий процесс (lint → test → build → деплой на staging при слиянии в main), и он выдаст YAML с корректными зависимостями задач, кэшированием и обработкой переменных окружения.

### Infrastructure as Code

Claude Code помогает с Terraform, Pulumi, CloudFormation и Ansible. Типичные паттерны:

- **Terraform**: генерировать блоки ресурсов для новых сервисов, рефакторить модули, диагностировать диффы `plan`, которые не соответствуют ожиданиям, писать выражения `locals` и `for_each`
- **Ansible**: писать playbook-и для провизионирования серверов, генерировать структуры ролей, отлаживать проблемы `become` и идемпотентности
- **CloudFormation**: конвертировать между CloudFormation и CDK, генерировать IAM-политики по принципу наименьших привилегий, объяснять состояния `UPDATE_ROLLBACK_FAILED`

С [MCP-сервером Terraform](/services/mcp-integration) Claude также может читать ваш существующий state и генерировать изменения, согласованные с уже развёрнутым.

### Автоматизация Runbook-ов

Runbook-и, живущие как страницы Confluence или Notion, ценны, но редко выполняются точно так, как написаны. Claude Code может:

- Преобразовать runbook в виде прозы в исполняемый shell-скрипт с правильной обработкой ошибок
- Добавить контрольные точки наблюдаемости (логировать результат каждого шага)
- Сгенерировать структурированный чеклист инцидента из post-mortem
- Перевести ручные шаги в Ansible-playbook-и или команды kubectl

Результат: runbook-и, которые действительно выполняются, с сохранёнными институциональными знаниями в комментариях.

## Реальный Пример DevOps-Рабочего Процесса

Вот как DevOps-инженер может использовать Claude Code для обработки инцидента:

**Ситуация**: Kubernetes-под регулярно убивается из-за OOM. PagerDuty срабатывает в 2 ночи.

**Ход сессии**:

1. Откройте Claude Code. Вставьте описание пода и недавние логи.
2. Claude определяет, что лимит памяти установлен на 128Mi, но JVM heap настроен на 256Mi — распространённая ошибка конфигурации.
3. Попросите Claude сгенерировать исправленные лимиты ресурсов и HPA с масштабированием по памяти.
4. Claude пишет YAML, объясняет расчёт и замечает, что таймаут health check также следует увеличить.
5. Применяете через `kubectl apply`, подтверждаете развёртывание.
6. Просите Claude написать черновик post-mortem с хронологией и первопричиной.

Общее время: 15 минут вместо 45. Никаких вкладок Stack Overflow. Никакого переключения контекста.

## Подключение Claude Code к вашей Инфраструктуре

Настоящий множитель мощности для DevOps — это совместная работа Claude Code с MCP-серверами, которые могут обращаться к вашим системам:

- **kubectl / Helm MCP** — проверять статус подов, читать логи, отслеживать прогресс развёртывания
- **AWS / GCP / Azure MCP** — описывать ресурсы, проверять алерты CloudWatch, получать данные Cost Explorer
- **Datadog / Grafana MCP** — загружать метрики и состояния алертов в контекст сессии
- **Terraform Cloud MCP** — читать состояние рабочего пространства и историю запусков

С этими интеграциями вам не нужно вставлять логи в сессию — Claude читает их напрямую из вашего стека наблюдаемости. Мы создаём и настраиваем эти интеграции в рамках нашего [сервиса интеграции MCP](/services/mcp-integration).

## Шаблоны Промптов для DevOps

**Для генерации инфраструктуры:**
> «Сгенерируй [тип ресурса] для [имя сервиса]. Ограничения: [список]. Должно соответствовать [соглашению]. Вывод в [формате].»

**Для отладки:**
> «Вот вывод ошибки: [вставить]. Ожидаемое поведение — [X]. Диагностируй первопричину и предложи исправление.»

**Для ревью:**
> «Проверь этот [Dockerfile / план Terraform / конфиг CI] на проблемы безопасности, проблемы производительности и отклонения от лучших практик. Будь конкретным.»

**Для документации:**
> «Преобразуй этот runbook в исполняемый скрипт. Сохрани всю условную логику. Добавь обработку ошибок и логирование. Прокомментируй неочевидные шаги.»
