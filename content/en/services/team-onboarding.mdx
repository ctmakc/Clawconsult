# Claude Code Team Onboarding

Handing your team a new AI tool and hoping they figure it out doesn't work. Developers revert to old habits, adoption stalls, and the productivity gains never materialize. Effective onboarding changes that.

Our **Claude Code team onboarding program** gives your engineering team the context, configuration, and habits they need to use Claude Code productively from day one — not month three.

## What's Included

### Group Onboarding Session

A live, interactive session (remote or onsite in Ottawa) covering:

- **What Claude Code actually is** — the model, the CLI, the tool use architecture, and how it differs from Copilot or ChatGPT
- **Live demos of real workflows** — PR review, test writing, debugging with subagents, MCP-powered database queries
- **Prompt patterns that work** — how to frame requests so Claude produces useful, correct output; how to course-correct when it doesn't
- **The skill system** — how to invoke built-in skills, how to write your own, and when to use skills vs. freeform prompts
- **When NOT to use Claude Code** — avoiding the failure modes that frustrate developers and erode trust in the tool

Sessions run 2–3 hours for groups up to 15. Larger groups get split sessions. All sessions are recorded and delivered to you for async review.

### CLAUDE.md Setup Per Repository

The single highest-leverage configuration for a team. We write `CLAUDE.md` files for each of your active repositories that encode:

- Stack and framework context (no more explaining your ORM every session)
- Coding conventions and style guide enforcement
- Test patterns and coverage expectations
- Git workflow (branch naming, commit message format, PR requirements)
- Architecture notes and known constraints
- Links to internal documentation Claude should reference

These files are committed to version control so every developer and every new hire gets the same Claude experience automatically.

### Skills Library

We install and configure a shared skills library tailored to your team's common tasks. Skills are reusable, invokable workflows that Claude executes on demand. We configure:

- `commit-commands` — standardized commit + PR creation with your team's conventions
- `pr-review` — structured PR review with security, coverage, and convention checks
- `systematic-debugging` — guided bug investigation protocol
- `test-driven-development` — TDD enforcement loop
- Domain-specific skills for your stack (Next.js deployment skills, Django migration skills, etc.)

### Hooks Configuration

Hooks automate the guardrails your team needs. We configure:

- Pre-commit hooks that run your linter and test suite before Claude commits
- Post-edit auto-formatting hooks
- Safety hooks that pause before destructive operations
- Notification hooks for long-running agent tasks

Hooks are configured at the project level and committed alongside your CLAUDE.md files.

### 30-Day Follow-Up Support

After the session, your team will have questions that didn't surface until they tried to do real work. Our 30-day follow-up includes:

- Async Q&A via a shared Slack channel or email thread
- One follow-up group call (30 minutes) at the two-week mark
- Updates to CLAUDE.md files and skills as you discover what's missing
- Escalation path for anything that needs a deeper configuration session

## Frequently Asked Questions

**How technical does the onboarding session get?**

We calibrate the session to your team's level during a pre-session call with the organizer. A team of senior backend engineers gets different depth than a mixed team with junior developers. We always run live demos, not slides.

**Do developers need anything pre-installed before the session?**

Yes. We send a pre-session checklist: Claude Code installed, Anthropic API key configured, and one test repository ready. The checklist takes about 20 minutes to complete. We send it one week before the session.

**Can we record the session for developers who can't attend live?**

Yes, all sessions are recorded by default. We deliver the recording within 24 hours. Developers who join async can ask questions via the follow-up support channel.

**What if our team uses multiple tech stacks?**

We write separate CLAUDE.md files per repository. If you have a Python backend and a React frontend, each gets a tailored file. Multi-stack teams are common — it's not a blocker.

**How do we maintain the CLAUDE.md files after onboarding?**

We document the conventions we followed so your team can update the files independently. Common triggers for updates: adding a new framework, changing your test strategy, onboarding a new repo. We recommend a quarterly CLAUDE.md review — we can do that as a lightweight async retainer.
